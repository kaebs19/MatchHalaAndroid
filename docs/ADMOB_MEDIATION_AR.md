# إعلانات هلا وربط الشبكات عبر AdMob

تحديث: 18 أكتوبر 2026. التطبيق `com.chathala.hala`.

## ما أصبح موجوداً في التطبيق

- بطاقة إعلانية واضحة داخل الاكتشاف، بزر متابعة متاح فوراً. لا نافذة انتظار ولا حجب للتصفح إذا لم يوجد إعلان جاهز.
- بطاقات البحث الإعلانية بعرض كامل مع وسائط كبيرة، ووسم إعلان مترجم، ومساحة مستقلة لـAdChoices، وألوان متوافقة مع الثيمين واتجاه العربية والإنجليزية.
- البيني في فواصل الاكتشاف فقط، بعد إكمال 20 بطاقة عند توفر الفرصة. البطاقة المدمجة لها الأولوية إذا تزامنت الفرصتان. لا بيني عند فتح المحادثة، ولا في أول دقيقة بعد العودة للمقدمة. الفاصل المشترك بين البينيّات 30 دقيقة.
- SDK لا يطلب إعلاناً قبل سماح UMP واكتمال التهيئة ومعرفة أن المستخدم غير مشترك. بيانات تسجيل الدخول المختصرة التي لا تحسم الاشتراك لا تفتح بوابة الإعلانات.
- التحميل بسياق Activity، وإيقاف عرض البانرات عند الخلفية، وإزالة الموارد المرتبطة بالشاشة عند تدميرها، وتجديد الإعلانات المخزنة القديمة.
- الخانات غير الممتلئة لا تعرض لوحة بانر فارغة. يعتمد تحديث البانر أثناء العرض على إعداد Auto refresh في وحدته داخل AdMob.
- فاحص إعلانات متاح من «حول التطبيق» في نسخة Debug فقط، مع سجل تشخيص للشبكة التي أعادت الإعلان.

## إعداد Unity وAdMob

1. في [Unity Monetization](https://cloud.unity.com/)، أنشئ مشروع Android للتطبيق واختر Google AdMob شريك الوساطة.
2. أنشئ مواضع **Bidding** للأشكال المطلوبة، واحتفظ بـAndroid Game ID وPlacement ID لكل شكل.
3. في AdMob افتح **Mediation → Create mediation group**. اختر Android وشكل الإعلان والبلدان، ثم اربط الوحدة الحالية المناسبة.
4. في **Bidding → Add ad source** اختر Unity Ads، وأكمل اتفاقية الشراكة. أضف mapping بالمعرّفين من Unity مع مطابقة شكل الإعلان والمنصة.
5. كرر المجموعة أو الربط للأشكال الأخرى المطلوبة. لا تستخدم معرّف Unity بدلاً من معرّف AdMob في التطبيق؛ AdMob يدير اختيار المصدر.

استخدم Bidding في الإعداد الجديد: أنهت Unity دعم Waterfall في 31 يناير 2026. التفاصيل: [خطوات Unity الرسمية](https://docs.unity.com/en-us/grow/dashboard/bidding/google)، [إعداد مصدر Unity في Google](https://developers.google.com/admob/android/mediation/unity).

## الخصوصية وملف البائعين

أضف Unity ضمن شركاء **Privacy & messaging** ثم أعد نشر الرسائل واختبر الموافقة والرفض. المحوّل الحالي يدعم إشارات GDPR عبر TCF/Additional Consent؛ لا يضع التطبيق قيمة موافقة مفترضة لجميع المستخدمين. راجع [إعداد TCF لدى Unity](https://docs.unity.com/en-us/grow/ads/privacy/gdpr/tcf-and-non-tcf-consent).

في الإصدار 2.5.0 تُطلب إعلانات Unity غير المخصصة عالمياً: يضبط التطبيق `privacy.consent=false` قبل تهيئة SDK وعند تحديث حالة UMP أو تغيير خيارات الخصوصية. لا تُحوّل `canRequestAds` أو غياب opt-out إلى موافقة على التخصيص، ولا تُمرّر قيمة `true` افتراضية. هذا قيد محافظ خاص بـUnity، وقد يقلل الطلب أو العائد مقارنة بالإعلانات المخصصة؛ لا يغير تخصيص AdMob الذي تديره UMP. تفاصيل الواجهة: [Unity privacy API](https://docs.unity.com/en-us/grow/ads/privacy/ccpa-compliance). دعم التخصيص مستقبلاً يحتاج قراءة اختيارات المستخدم الفعلية والتحقق من إشارات كل منطقة، ولا يكفي تفعيل الشريك في اللوحة.

انسخ سطور **app-ads.txt** التي يوفرها كل حساب، وضعها في جذر موقع المطوّر المسجل بمتجر Google Play، ثم تحقق من قبولها في اللوحتين. لا تفترض أن نطاق API هو موقع المطوّر، ولا تخمّن بيانات البائعين. [شرح Google لملف app-ads.txt](https://support.google.com/admob/answer/9363762).

## الاختبار

نسخة Debug العادية تستخدم وحدات Google التجريبية، وهي مخصصة لفحص الواجهة ولا تثبت تشغيل وساطة Unity.

لاختبار وحدات التطبيق الحقيقية على جهاز مسجّل للاختبار، فعّل Unity Test Mode من لوحة Unity، وسجّل الجهاز في AdMob وUnity، ثم ابنِ:

```bash
JAVA_HOME="/Users/mohammedsaleh/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home" \
./gradlew :app:assembleDebug \
  -PhalaMediationTest=true \
  -PhalaAdTestDeviceIds=YOUR_32_CHARACTER_TEST_DEVICE_ID
```

استبدل القيمة بمعرّف الاختبار الفعلي من سجل SDK. البناء يرفض هذا الوضع إذا لم تُمرَّر معرّفات اختبار صالحة الشكل. يمكن فصل عدة معرّفات بفاصلة. تُستخدم القيم أيضاً لاختبار UMP.

افتح الإعدادات ← حول التطبيق ← فحص الإعلانات، ثم اختبر Unity كمصدر منفرد وتحقق من بيانات الاستجابة. لا تختبر بالضغط على إعلانات إنتاجية. بعد الاختبار أوقف وضع Unity الاختباري قبل إصدار المتجر؛ حقول الاختبار الخاصة بالتطبيق محصورة في Debug. [فاحص إعلانات Google](https://developers.google.com/admob/android/ad-inspector).

## شبكات إضافية

| المصدر | متطلبات إضافته |
|---|---|
| Unity Ads | أصبح SDK والمحوّل داخل المشروع؛ تبقى إعدادات الحساب والربط والاختبار |
| AppLovin | SDK/adapter وإعداد المصدر وشروطه وخصوصيته؛ لم يُضف إلى البناء الحالي |
| Meta Audience Network | حساب ومواضع ومحوّل وربط bidding مناسب؛ لم يُضف إلى البناء الحالي |

تختلف الأشكال المدعومة بين الشبكات. مثلاً يبيّن دليل AppLovin الحالي أن بانراته لا تدعم bidding؛ لذلك لا تُكرر تكوين Unity لكل الأشكال دون مراجعة دليل الشبكة. [AppLovin مع AdMob](https://developers.google.com/admob/android/mediation/applovin)، [Meta مع AdMob](https://developers.google.com/admob/android/mediation/meta).

ابدأ بمصدر إضافي واحد، ثم قارن معدل التعبئة وزمن التحميل والعائد لكل ألف ظهور حسب البلد والشكل. زيادة عدد الشبكات وحدها لا تضمن زيادة الدخل.
